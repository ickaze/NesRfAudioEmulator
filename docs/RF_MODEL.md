# RFモデルと実機との差

## 以前の鳴り方が違った理由

0.2.1までの処理は、RGBフレームを音声サンプル数へ直接間引き、隣接画素の輝度差に
可聴帯域の任意の正弦波と60Hzを加え、そのノイズだけをローパスしていました。
水平帰線・垂直帰線、ブランキング、音声FM、受信機の帯域・同期引き込みを扱っていません。
このため画面内容と音の関係、ノイズのスペクトル、接触不良時の鳴り方に根本的な差がありました。

ローパスで波形を滑らかにすることも有効ですが、生成する信号と受信経路を変えないままでは
実機らしさを十分に改善できません。今回、旧方式を独立したRfProcessorへ置き換えました。

## 今回の信号経路

映像はRGBをYIQへ変換し、1画素4サンプル、1走査線1364サンプルの合成映像を作ります。
水平同期、ブランキング、バースト、垂直帰線の近似波形を含みます。
色副搬送波は6サンプル周期です。NTSC系では約21.48MHz相当になります。
NES PPUの生の6ビット色情報や強調ビット波形からの生成ではなく、コアが復号済みのRGBからの再構成です。
垂直帰線の等化パルス・奇偶フレーム短縮は簡略化しています。

各走査線で受信信号強度、同調による減衰、接触状態を算出します。
接触不良はランダムな断続状態と一次遅れによる回復として扱い、時定数を調整できます。
この同じ状態を映像処理と音声処理で使用します。
映像には遅延反射、帯域制限、雑音を加え、簡易Y/C分離でRGBへ戻します。
受信したバーストから色の位相と利得を補正します。
水平追従と垂直ロールは受信強度等から推定したロック状態を使う動作モデルです。
実際の同期分離回路やPLLをトランジスター単位で解く処理ではありません。

音声は48kHzのコア出力を192kHzへ線形補間し、75µsのプリエンファシス後、
最大偏移25kHzを基準とする複素FM信号へ変換します。
4.5MHzインターキャリアをそのまま192kHzでサンプリングするのではなく、
周波数変換後の等価ベースバンドを計算します。

- 合成映像を区間積分して音声側へ渡し、映像由来の位相擾乱を加える。
- 接触不良等による振幅低下と雑音を同じ時間区間へ加える。
- 隣接する複素サンプルの位相差でFM復調する。
- 75µsディエンファシス、63タップFIR、4:1間引き、DC除去、2段音声ローパスを通す。

これは映像の位相変動が音声検波へ漏れる現象を表す近似です。
混入係数、同調ずれの尺度、S/Nや同期ロックの対応は実測校正した値ではありません。

## 同期と音声の関係

画面の同期外れと音声の乱れが同時に発生するのは、共通の受信信号の劣化でも説明できます。
画面の水平/垂直ホールドずれだけを原因として、FM音声が必ず同じ割合で伸縮するわけではありません。
本実装では受信劣化を両者に反映し、受信機側の同期回路から音声への漏れは別項目にしました。
その項目が0なら、ホールドだけを変更しても音声ピッチは変化しません。
色位相や水平ジッター等、映像復号側だけの調整も、それだけでは音声を加工しません。

## 記憶の音へ寄せる調整例

まず「映像由来のバズが強い」を選び、映像→音声の混入と音声ローパスを調整してください。
画面が変わると音も変わるかを確認できます。
高域が耳につく場合は音声ローパスを下げます。
接触時の変化を緩やかにする場合は、接触変化の時定数を上げます。
同期回路の音が強すぎる場合は、同期回路→音声の漏れを下げます。
これらは調整の開始点であり、特定のテレビの再現値ではありません。

## 残る差

- RGB化の前にあった実PPUの波形・パレット非線形・色強調の電圧特性。
- VHF/UHFの実搬送波、VSB側波帯、SAW/IFフィルターの正確な群遅延。
- RFスイッチ、ケーブル、接点、接地、テレビ内部の電源や偏向回路の個別特性。
- テレビのアンプ・スピーカーの周波数特性と筐体共振。
- PALの位相交替や音声時定数。PAL/DendyのRF表示は走査周波数を追従するNTSC型近似。

したがって、現段階の表現は「RF接続の劣化と映像音声連動を調整するモデル」です。
記憶にある特定の実機と同じ音であることは保証していません。
映像と同時に録った実機音声があれば、混入スペクトルや時定数の校正に使えます。

## 0.4.0: 非同期処理と隣接入力

RFの状態はワーカースレッドだけが更新し、主スレッドからはコピーした映像・音声と設定を渡します。
待ち行列の上限は4で、受信結果もこの枠に含みます。ROM切り替え等で世代が変わると古い結果は受け取りません。
別ウインドウはMedia Foundationの別デコードスレッドからデータを受け取ります。

隣接映像は別動画のRGBを合成映像相当へ変換し、±6MHzの搬送波オフセットを持つAM成分として加えます。
上下で簡略化した抑圧率を変えています。制御値は実際のアンテナ入力電圧ではなく、IF選択度通過後の漏れの大きさです。
隣接音声は復調後漏話に相当する信号としてFM処理前へ加えます。
このため、隣接FM信号と希望FM信号の高周波での競合・捕捉効果まで完全に再現するものではありません。

動画デコードにはMicrosoft Media Foundation Source Readerを使用します。
参考: https://learn.microsoft.com/en-us/windows/win32/medfound/processing-media-data-with-the-source-reader

YouTubeページを対象にするなら、別途ウインドウ映像キャプチャとブラウザープロセスの音声取得が必要です。
システム音声全体のループバックでは本アプリ自身の出力も拾ってしまうため、プロセス単位の取得が適します。
今回の実装には含めていません。
参考:
https://learn.microsoft.com/en-us/windows/uwp/audio-video-camera/screen-capture
https://learn.microsoft.com/en-us/samples/microsoft/windows-classic-samples/applicationloopbackaudio-sample/

## 0.4.1: 明るさに依存する音声漏れ

位相擾乱だけでは、FM復調の差分とディエンファシスで低域の輝度依存成分が弱くなります。
受信合成映像の区間平均を、検波後の音声へ混入量×0.5×受信利得で加える近似を追加しました。
既存のディエンファシス、DC除去、音声ローパスを通します。一定の輝度をそのままDC音声にするのではなく、
有効画面と垂直/水平帰線期間の差がバズになります。独立した60Hz発振器は使っていません。
同じ受信映像を使うため、接触不良や隣接映像の影響も含まれます。
係数は操作感のための調整で、特定の実機テレビの測定に基づく校正値ではありません。
